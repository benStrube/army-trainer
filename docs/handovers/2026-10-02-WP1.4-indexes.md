## Not done / known issues
- **Directives are lexical, not judged.** `may` often states capability and `will` often predicts. The planner (Opus) must decide which are real requirements; filter fields are `strength`, `section`, `possibly_historical`.
- Sentence splitting is rule-based; tables flattened into text (e.g. para A-20) yield long junk sentences.
- Roles only come from glossary acronyms and the personnel/command-post headings. Some headings from "…COMMAND POSTS" have 0 text mentions. "Soldier"-type roles are not found.
- 13 of 91 checked internal table/figure/paragraph references don't resolve to a node in the tree (e.g. table 3-5, 3-6, A-1, A-2, A-7, A-8, E-1). Probably tables the converter did not produce; not investigated.
- Deadlines are rare in an FM (about 36) and several are not Soldier requirements (a history quote, report formats).
- No changes were made to Opus-owned files (`structure/models.py`, `schemas/*.json`, `docs/doc_tree.md`). No new tree fields were needed.

## Decisions made
- Index file is separate from the tree (`<ID>.indexes.json`), with `index_version: "1.0"`. No JSON schema for it yet; Opus may want one if the planner packet (WP 2.2) consumes it.
- Role names for squashed headings are recovered by word-segmenting against the document's own vocabulary (no hand-written role list).
- `NLT`/`NET` match only in capitals (otherwise "net" the radio network matched).
